Redis Distributed Locks with Atomic Lua ⚡

How we eliminated double-bookings and duplicate bill settlements across concurrent server clusters:

// backend/utils/distributedLock.ts export async function withDistributedLock<T>( lockKey: string, ttlMs = 5000, operation: () => Promise<T> ): Promise<T> { const fullKey = `lock:${lockKey}`; const token = crypto.randomUUID(); // 1. SET lock:key token PX 5000 NX const acquired = await redis.set(fullKey, token, 'PX', ttlMs, 'NX'); if (!acquired) throw new AppError('CONCURRENCY_LOCK_ACTIVE', 'Busy', 409); try { return await operation(); } finally { // 2. Atomic Lua script ensures token ownership before deleting const lua = `if redis.call("get",KEYS[1])==ARGV[1] then return redis.call("del",KEYS[1]) else return 0 end`; await redis.eval(lua, 1, fullKey, token); } }
✓ Scoped Resources:

bill:${id}, stripe:${sessionId}, escrow:${id}

✓ Local Fallback:

Graceful fallback to InMemoryMutex if Redis is offline.

9/10 Security Score 🛡️

Bank-Grade Security Architecture 🔐

Audited and verified against real-world production threat vectors:

🍪
httpOnly Cookie JWTs

Tokens transmitted exclusively in httpOnly, SameSite cookies — zero XSS token theft via JavaScript.

🚫
Redis Token Blacklist

Revoked tokens written to Redis bl_${token} with TTL matching JWT expiry for instant stateless revocation.

🧹
NoSQL Injection Sanitizer

Custom recursive middleware strips malicious MongoDB $ keys and dots from all request payloads.

🔑
Granular RBAC Engine

Strict hasPermission('manage:escrow') applied across all 35+ routes (bills, visitors, escrow, parking).
